# Proposed engine-ingress equipment admission boundary

This is an integration proposal only. No production file was changed by this
investigation. The completed raw perception baseline must remain immutable.

## Minimal integration point

In `sports/badminton/src/bai_badminton/engine.py::_append`, before constructing
the `persons` list and before camera stabilization, create a distinct semantic
copy of every `PersonObs`. Evaluate the selected raw racket candidate against
all current raw-image person poses. Admit unaliased candidates; for a positive
anatomical alias, remove only `racket` and `racket_frame_idx` from that owner's
semantic copy. Do not re-run candidate selection or promote a runner-up.

Illustrative diff, not applied:

```diff
@@ _append, immediately before the existing persons = expression
+        semantic_people, ambiguities = admit_racket_candidates(
+            fp.persons, frame_idx=fp.frame_idx
+        )
         persons = (
-            [_stabilise(p, Ginv, ...) for p in fp.persons]
+            [_stabilise(p, Ginv, ...) for p in semantic_people]
             if Ginv is not None
-            else fp.persons
+            else semantic_people
         )
+        self._emit(racket_ambiguity_events(ambiguities, fp.frame_idx))
```

The admission helper would always return new dataclass copies, including
unaffected owners. For ambiguous candidates it uses
`replace(person, racket=None, racket_frame_idx=None)`; it never modifies the
input person, pose array, candidate or `FramePerception`. Copying unaffected
owners also avoids aliasing the engine's later `court_xy` assignments into raw
input when the no-stabilization branch would otherwise reuse `fp.persons`.

A small badminton-domain pure helper is preferable to changing `RacketPort` or
adding badminton anatomy rules to the generic engine host. The source frame is
already available here, so no image-detector component API change is needed.

## Admission contract

- Apply the narrow ambiguity rule only to the supported geometric racket
  candidate interpretation, with a current source-stamped racket candidate.
- Require fresh detector-matched anatomy and `pose_frame_idx==frame_idx`.
- Require finite COCO facial landmarks with confidence0.5–1; at least three
  different landmark indices and distinct image positions lie inside the fitted
  ellipse. This is positive ambiguity evidence, not a body/head region mask.
- Inspect all current target participants, including another person's head.
- Missing/low-confidence/stale or collapsed face poses do not invent an alias.
- Keep the original candidate and its geometric score as raw evidence.
- Do not replace wrists or satisfy a specific equipment-overlap cue with the
  ambiguous candidate in the semantic engine copy.
- Do not claim that surviving geometric candidates are verified rackets.

The proposed rule should record its own policy/version. It changes semantic
admission, not the neural model or raw perception cache identity. Semantic
results must be recomputed after the policy changes; old accepted events must
not be silently reused as though generated by the new rule.

## Consumer trace

| Consumer | Existing source | Effect of ingress gating |
|---|---|---|
| Current participant snapshots | `_append`, `ParticipantSnapshot(racket=person.racket)` | Gated copy supplies `None` and no racket source stamp. |
| Anonymous participant contact windows | `participant_contact.py::participant_window` | Receives snapshots containing only admitted equipment. |
| Named player temporal buffers | `_append`, `buf['racket'].append(a.racket)` | Identity resolver sees gated people; named windows receive no ambiguous racket. |
| Contact proximity anchor | `events/contact.py::_player_point` | Falls back to posed wrists instead of replacing them with the head ellipse. |
| Racket overlap score | `events/contact.py::score_frame` | Ambiguous ellipse cannot supply overlap support. |
| Fresh equipment observation frames | `_contact_with_observation_evidence` | Snapshot has no racket and no source stamp, so the physical-evidence gate cannot call it observed equipment. |
| Raw racket track export | `_append` loop over `fp.persons` | Still exports raw candidate if retained deliberately; it must remain explicitly described as raw geometric evidence. |
| Original perception cache/overlays | Original `fp.persons`; `plugin.encode_perception` | Unchanged candidate remains available for diagnosis and overlay. |

Current contact scoring reads the semantic window/snapshot arrays, not
`TrackObject.RACKET` Parquet rows. A repository source search found the raw
racket track export as the only direct post-gate raw `fp.persons` racket path.
Canonical movement/heatmaps read player/camera tracks and stroke events, not
raw racket tracks. External clients or future consumers could read raw tracks;
their candidate status must not be presented as semantic acceptance.

The runtime writes the perception cache in `_perceive` **before** calling
`sport.ingest`. Non-mutating copies still matter: semantic replay also passes
decoded objects to the engine, and tests should verify raw objects/bytes remain
unchanged before and after ingestion.

## Explicit ambiguity evidence

Use a provisional domain event such as `racket_observation_ambiguity`, distinct
from player identity ambiguity or a verified physical rejection. Its payload
should include policy/version, reason `racket_anatomical_alias`, frame/source
stamps, raw owner track ID, original candidate geometry/heuristic support,
implicated face-track IDs and landmark indices, and `semantic_admitted=false`.

This preserves the reason without changing raw cache schema or claiming a
head classification. Warning events do not create a contact, named player,
winner or score. The contact evidence remains unavailable for this equipment
cue. Reporting should distinguish raw candidate count, semantic admission and
abstention counts.

## Regression plan

1. Add helper contract tests corresponding to the17 diagnosis-local GREEN cases:
   clear racket, near-head but disjoint racket, explicit face overlap, cross-person
   head/doubles, rotation/scale, low/missing/stale/collapsed landmarks, whole-owner
   abstention and no lower-ranked junk promotion.
2. Test actual `_append` with fixed/no-camera and registered camera branches.
   Verify original dataclass fields, arrays, racket/source stamps and encoded
   cache bytes remain unchanged. Gate in raw image coordinates before projective
   stabilization to avoid fitting a different ambiguity predicate after warping.
3. For both named singles and anonymous participant/doubles paths, verify
   `_players['racket']`, participant snapshots and reconstructed windows omit
   ambiguous equipment; contact proximity uses wrists and fresh-racket evidence
   is false. Preserve unrelated owners' racket observations and pose evidence.
4. Verify a source-bound ambiguity event contains the exact original candidate
   and no named actor/point. If raw track export remains, assert it is unchanged
   and paired with explicit semantic-admission diagnostics.
5. Test chunk partitioning, checkpoint/resume and correction handling so an
   admission warning cannot silently duplicate accepted sporting events.
6. Preserve Test2 and Test1 perception hashes. Establish strict own-cache baseline
   parity first, then run a declared one-variable semantic source intervention
   and compare contact/classification/rally/outcome/abstention results. Do not
   call these fresh neural inference or treat old raw-candidate counts as the
   new semantic-admission count.

## Reusing exact perception without weakening provenance

`research/production_external_semantic_replay.py` already supports
`--source-intervention` with `--baseline-proof`. Its normal mode correctly rejects
changed sport source. The intervention manifest binds the complete source delta,
current source hashes, original completed inference receipt and strict baseline
parity proof. Use that explicit path rather than weakening the normal completion
guard or rewriting original inference receipts.

An ingress-only semantic change does not alter the image/pose/racket detector.
Exact own-cache replay is therefore useful for isolating its effects. A subsequent
fresh full pipeline integration run still establishes actual end-to-end behavior;
any waived fresh neural rerun must remain an explicit scope decision, not a claim
that the replay was fresh inference.

## Remaining limits

The far banner/letter candidates and some torso candidates remain unresolved.
True racket/face overlap may lose a usable cue; erroneous face poses may create
abstention. Missing facial evidence cannot certify equipment. Count reductions
are not physical precision/recall improvements. The proposed boundary protects
interpretation while retaining the raw evidence needed for better perception.
