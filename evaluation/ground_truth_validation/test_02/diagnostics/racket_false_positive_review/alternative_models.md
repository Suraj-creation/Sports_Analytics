# Test 2 racket/contact alternatives: evidence and adoption prerequisites

Research only, checked **2026-11-11**. No weights, datasets or packages were downloaded; no model/configuration was replaced. This review starts from the actual fresh frame300 head-adjacent ellipse failures and source-bound component panels, not advertised benchmark scores.

## Local evidence first

`models/manifest.yaml` declares the active built-in `racket_geometry_v1` and a **candidate** `racketvision_racketpose` pointing only to `best_PCK_epoch_90.pth`, with `pin-on-first-fetch`. `models/cache/` currently has no RacketVision/HitNet weights. A pose-only manifest entry is insufficient to run a complete racket detector. The declared MIT label does not independently establish checkpoint rights or authenticity.

Existing [model research](../../../../../docs/research/model-and-algorithm-evaluation.md) already identified this missing two-stage adapter and unresolved model-card terms. The retained [contact study](../../../../../docs/research/badmintonai-contact-study-20261103.md) examined visibility-gap, serve-onset and wrist-motion ideas. Current `events/contact.py` already uses shuttle velocity change, proximity and wrist motion, so reintroducing the same cues is not a new improvement. Preserve the completed Test1 fixes and Test2 baseline; evaluate only a specific missing capability through the existing replaceable component contracts.

## Evidence-backed candidates

### 1. RacketVision RTMDet-M plus racket-specific RTMPose-M

The authors release a complete **racket-box detector followed by five racket keypoints**—top, bottom, handle, left and right. Its output can provide object-specific shape/handle evidence beyond an ellipse near a human wrist. It remains racket perception, not a trained physical-contact verifier. The official inference contract returns a variable list of rackets per frame; player ownership and persistence remain separate work. [Official RacketPose implementation](https://github.com/OrcustD/RacketVision/blob/c44af2a08524d3cb54d818f19686f4cdea4d2793/source/RacketPose/README.md).

Both required checkpoints, **`epoch_300.pth`** (detector) and **`best_PCK_epoch_90.pth`** (pose), are currently listed by the author-linked host; the official downloader maps both to RacketPose. The local manifest lists only the latter. Host revision observed: `a3760773233a0988c9605259743fbdd87c59d3a3`. Availability was checked by listing, not download/deserialization. [Author checkpoint mapping](https://github.com/OrcustD/RacketVision/blob/c44af2a08524d3cb54d818f19686f4cdea4d2793/source/download_checkpoints.py), [checkpoint listing](https://huggingface.co/linfeng302/RacketVision-Models/tree/a3760773233a0988c9605259743fbdd87c59d3a3/checkpoints).

**Licences separately:** repository code is **MIT**; MMDetection and MMPose code are **Apache-2.0**. The model host has **no model card or separately listed LICENSE**, so explicit terms for these exact two checkpoints remain unverified. The dataset card declares **MIT**; the paper says footage comes from professional broadcasts on YouTube, which does not establish redistribution/training rights to every underlying video. Preserve these distinctions. [RacketVision code licence](https://github.com/OrcustD/RacketVision/blob/c44af2a08524d3cb54d818f19686f4cdea4d2793/LICENSE), [MMDetection](https://github.com/open-mmlab/mmdetection/blob/main/LICENSE), [MMPose](https://github.com/open-mmlab/mmpose/blob/main/LICENSE), [model host](https://huggingface.co/linfeng302/RacketVision-Models), [dataset card](https://huggingface.co/datasets/linfeng302/RacketVision), [paper: data collection](https://arxiv.org/html/2511.17045v3#S3.SS1).

**Singles/doubles:** multiple outputs do not establish four-player owner/contact attribution. No doubles-specific owner/contact validation was verified in the inspected release. Benchmark both formats independently, including overlapping rackets, teammates, occlusion and adjacent courts. Practical prerequisites: verify checkpoint grants/digests; reproduce preprocessing and five-point ordering; isolated compatible OpenMMLab/export environment; validate native/export parity and Pascal runtime; map racket handle to a current observed wrist with ambiguous ownership preserved. Do not install its environment over the working baseline.

### 2. MonoTrack HitNet: learned temporal hit spotting from pose and shuttle motion

The authors' `MLHitDetector` uses a bidirectional recurrent model over pose, shuttle and court features, with no-hit/bottom-player/top-player outputs. It offers a temporal alternative to making a static ellipse the decisive contact cue. The source also supplies an ad-hoc trajectory-extrema/reachability comparator. **Neither directly detects a racket.** [Author hit-detector source](https://github.com/jhwang7628/monotrack/blob/39e9227bd44fa2a579731b1cc97c7f529f391cd6/python/ai-badminton/src/ai_badminton/hit_detector.py).

**Availability:** training notebooks exist, but the inspected pipeline references `hitnet_conv_model_predict_direction-12-6-0.h5` under a developer's absolute local model path. No public released HitNet artifact, authoritative digest or model card was verified in the inspected repository tree/README. Treat it as an implementation/research lead, not an available drop-in pretrained replacement. [Pipeline model reference](https://github.com/jhwang7628/monotrack/blob/39e9227bd44fa2a579731b1cc97c7f529f391cd6/python/ai-badminton/src/ai_badminton/pipeline_clean.py), [author setup/training instructions](https://github.com/jhwang7628/monotrack).

**Licences separately:** root code is **Adobe Research License**, expressly **noncommercial research/teaching only**, including a restriction on developing commercial products. It is **not MIT**. Exact HitNet weight terms and underlying training-video/annotation rights were not independently established. The root licence cannot be assumed to settle third-party MMPose/MMDetection/TrackNet assets. This is not a production-adoption candidate under the verified grant. [Author licence](https://github.com/jhwang7628/monotrack/blob/39e9227bd44fa2a579731b1cc97c7f529f391cd6/LICENSE).

**Singles/doubles:** the released classifier and dynamic-programming postprocessing explicitly model two players and alternating hitters. It cannot attribute four doubles players without a new contract/model/labels. Its bidirectional temporal window and explicit timing offsets require an offline/latency declaration. Practical prerequisites: clarify permitted use and exact weights; reproduce frame/sample alignment; independently label contacts and negatives; compare a temporal spotter in isolation from outcome/scoring. No source was copied into production.

### 3. A bounded complementary motion-cue ablation, retaining current perceptions

BadmintonAI's author source combines trajectory acceleration/turns, serve onset and wrist-speed candidates. This can inform a specifically measured missing-contact ablation **without importing a new racket model**. It also illustrates why candidate generation, actor attribution and confirmed physical contact must remain separate. Its match-specific offsets, pixel thresholds and interpolation cannot be transferred to Test2 as facts. Existing overlap with our current component means the exact proposed difference must be demonstrated first. [Pinned author hit implementation](https://github.com/jayclim/BadmintonAI/blob/5c356f05cde0ed90c75316c133e0aba495e5232b/src/badminton/hits.py).

**Licences separately:** original algorithm code is **MIT**. There is no separate trained checkpoint for those rule cues. The complete external stack includes Ultralytics code/models under **AGPL-3.0** according to its own explicit licence inventory; adopting that entire stack has different terms from studying its original cue code. CoachAI's repository supplies an MIT software licence, but annotation and BWF/YouTube footage rights still need dataset-specific verification. [Original code licence](https://github.com/jayclim/BadmintonAI/blob/5c356f05cde0ed90c75316c133e0aba495e5232b/LICENSE), [author dependency inventory](https://github.com/jayclim/BadmintonAI/blob/5c356f05cde0ed90c75316c133e0aba495e5232b/LICENSES/README.md), [CoachAI licence](https://github.com/wywyWang/CoachAI-Projects/blob/main/LICENSE).

**Singles/doubles:** the author distinguishes its singles hit chain from a separate doubles tracking/formation surface; its README explicitly says four-slot hit attribution is not built. Do not call its doubles tracking coverage contact accuracy. Our possible ablation must support all current participants and explicit ambiguity, rather than importing two-player alternation. [Author scope declaration](https://github.com/jayclim/BadmintonAI/tree/5c356f05cde0ed90c75316c133e0aba495e5232b#doubles).

## Required comparison before selection

**Part2 Test2 has no independently reviewed racket boxes/keypoints, physical contact times, exhaustive negative windows or hitter identities.** Generated player/shuttle/winner tables and agent visual panels cannot supply those denominators. No alternative has been measured on this source, and no performance improvement is claimed here.

First preserve a source-bound review set containing visible racket positives, occluded/absent cases, head/banner/jersey/line distractors, serve and net exchanges, current wrist/owner ambiguity, cuts and all four players in separate doubles recordings. Record reviewer status, exact frames/PTS and visibility; keep match-disjoint development and regression/holdout sets. Test1/Test2 are exposed development material, not newly blind holdouts.

Then compare one change at a time: racket box/keypoint localization and owner attribution; contact one-to-one precision/recall/F1 at declared frame tolerances; false contacts per minute; conditional versus end-to-end hitter/class coverage; unknown/abstention and downstream rally/score effects. Include full-run cases with no labels where only coverage is reportable. Preserve current perceptions/configuration for cue ablations and separately record model/preprocessing changes for neural candidates. Measure actual CPU/GPU memory, total runtime and processing latency on the existing server; artifact size or upstream leaderboard values do not establish them.

The closest object-specific candidate is **the complete RacketVision detector-plus-pose pair**, subject to unresolved checkpoint terms, integration and independent labels. MonoTrack remains a restricted research reference. Motion cues are a controlled ablation opportunity only where diagnosis identifies a genuinely missing signal. No generic detector upgrade or unverified leaderboard result justifies replacing the current baseline.
