# OCR acquisition completeness: contract review and unresolved design gate

**Do not promote an acquisition change from this study.** The generic successful-but-stale ROI defect is real, but it is not the cause established for the actual Test 2 105-call gap. A full-corner-only replacement has zero measured gap benefit and loses the valid 22924 primary reading. The proposed change here is an **unregistered diagnostic evidence contract**, not a repaired production reader or a coverage improvement.

This review reads preserved source, raw OCR observations, source panels and completed diagnostic results. It runs only pure Python/NumPy/parser/stub checks: **no OCR model, GPU, new media decoding, download, production edit, annotation edit or Test 3 access**. Source snapshots and the input hashes are retained in [input_manifest.json](input_manifest.json). No prior experiment was rerun.

## Exact code path and missing guarantee

The existing [reader snapshot](source_snapshots/scoreboard.py) calls OCR once per eligible `every`-frame interval. It searches one of four corners while unlocked, then narrows to the parsed board bounds with the existing margin. A miss increments `_misses`; the existing budget unlocks. Any successful parse resets `_misses=0`. A successful locked read does not update `roi`.

`parse_scoreboard` groups spatially coherent competitor names and numeric fields, associates a field with its nearest eligible name, chooses the rightmost supplied numeric field and requires one aligned two-row board. It rejects missing/misaligned fields and multiple plausible boards. Its bounds include consumed text only, deliberately excluding unrelated branding. This parser does **not** inspect pixels outside the OCR crop and does not observe a board-panel boundary or an exhaustive score-column layout. Its “rightmost” property is conditional on supplied pixels.

Consequently a new current column can appear outside a narrow locked crop while the retained completed-game column remains perfectly parseable. Every successful stale parse resets misses, so miss-based recovery cannot guarantee reacquisition. Repeating OCR on the same incomplete crop or raising confidence does not reveal excluded pixels. The contract checks include two full images with identical crop pixels and a change entirely outside that crop: no crop-only classifier can distinguish those worlds.

The current [`ScoreReading`](source_snapshots/perception_types.py) retains frame, rows, optional games, confidence and source-view/replay context, but not raw OCR, crop bounds, selected token indices or acquisition completeness. Two corroborated readings in [`ScoreReconciler`](source_snapshots/score_ocr.py) corroborate repeated model text, not completeness of the current column. Two identical stale crops can therefore be corroborated without proving which game column was read. This is distinct from named player/team binding and accepted point decisions.

The actual [`_read_scoreboard`](source_snapshots/pipeline.py) uses the existing scene eligibility and reader cadence. Its stale docstring about reading only between rallies does not describe the executable loop: `in_play` is not used to gate these calls. This study changes neither behavior nor cadence.

## Reusable proposal with explicit boundaries

Keep the current primary reader, model/checkpoints, thresholds, eligible calls, miss budget and original successful22924 observation unchanged. Introduce evidence instrumentation first, as a separately versioned proposal with these contracts:

1. **Acquisition attempt.** Record canonical frame, source pixel hash/shape, crop pixel hash and image-space rectangle, model/provider fingerprint, call eligibility, call/miss/corner/ROI state before and after, and all raw quadrilaterals/text/confidences. Record misses and parser abstentions as well as successes. Keep true unknown raw data as null. Generic image/model provenance belongs at the existing host evidence boundary; badminton interpretation remains in the plugin.
2. **Parser selection.** Record the exact selected source-token indices, row grouping, numeric-token/character spans and ordering used by the unchanged parser. Call its scope `rightmost_parseable_field_in_supplied_pixels`. Do not silently relabel a token as a verified current-game field or convert raw recognition confidence into calibrated accuracy. Cropped parse success implies neither panel completeness nor named identity.
3. **Optional layout-context provider.** A replaceable provider may propose source-bound board envelope, row bands, column/cell boundaries and visible external context. It must declare observed versus hypothesised geometry, supported layouts, ambiguity/unsupported states, exact source frame/coordinates, producer version, and epoch/reset behavior. A text-token envelope is not a complete board envelope. A score-like number to the right is not itself proof of another valid column. Current default is **unknown**, not an automatic new layout detector.
4. **Completeness assessment.** Only independent, same-source, validated panel/cell context could show whether the crop includes the observed panel extent and whether a selected field has an unobserved right continuation. “Includes observed panel extent” still does not prove active-game semantics or correct recognition. Any clipped/ambiguous/unsupported layout remains unknown. Old layout geometry requires explicit current-frame verification and must be invalidated on edits, format/image changes or unverified graphic changes; repeated successful text is insufficient verification.
5. **Downstream provenance.** Preserve original primary observations and the known22924 positive even if completeness is unknown. Separate `model_text_observation`, `layout_hypothesis`, `column_role`, `corroborated_observation`, `roster/team_binding` and `accepted_point`. An eventual stricter point consumer must be a separately benchmarked semantic change, not silently enabled by adding diagnostics. Old cache versions decode completeness as unknown; do not fabricate missing raw/crop evidence or rewrite historical caches.

[observation_scope_proposal.py](observation_scope_proposal.py) demonstrates only items1/2's uncertainty boundary on supplied metadata: it preserves raw/primary observations, rejects foreign frame/crop bindings, and has **no mechanism that promotes confidence or a boolean into verified completeness**. It performs zero extra OCR calls and is not registered/imported by production. It does not implement a layout detector, select a new crop, modify `ScoreReading`, or fix the stale loop. A proposed evidence schema is in [proposal_contract.json](proposal_contract.json).

### Why no automatic layout fix is justified yet

The inspected broadcast graphics visibly have aligned panels and separators, so source-supported layout context is technically plausible. But these examples do not validate a reusable panel detector. There is no retained model output providing independent panel/cell boundaries, nor an independently reviewed mixed-layout test set. A bespoke threshold chosen to recover this broadcaster would be tuning on the failure. Image edges can also be absent, antialiased, animated, shared with court signage or occur beside a sponsor. Continuous text/doubles names and logos may cross the same rows. A whole full corner contains competing text and changes recognition, as22924 directly demonstrates.

Pure pixel change outside the ROI could request **review/reacquisition**, but cannot certify a score column: unrelated motion, a logo animation or an adjacent mini-score creates the same signal. Pixel stability cannot certify completeness either: a current column may already exist outside the crop when the lock is created. A fixed right margin or frame/game-specific expansion is not a completeness guarantee. Reacquisition on every success using the full corner simply repeats the rejected candidate.

Under a strict one-OCR-call-per-eligible-frame budget, replacing a primary call with a context call necessarily risks losing a primary positive; the observed22924 countercontrol prevents claiming preservation. Running an additional context OCR lane would relax the budget and add an independently measured runtime/ambiguity tradeoff. It requires a new bounded authorization and experiment, not an implicit part of this study. A non-neural layout provider might avoid additional OCR calls, but still requires labelled layout evidence and countercontrols before it can influence crop/score semantics.

## Validation prerequisites and disposition

Before any production proposal, preserve the exact current primary path as a control and collect independently reviewed panel/cell/continuation labels across games, ordinary reads, layout growth/shrinkage, missing/fused digits, logos, multiple boards, cuts, occlusion, animated graphics, alternate cameras and four-person doubles team-name layouts. Two rows are scoring slots, not proof of two physical participants. Keep recognition, layout completeness, column role, named identity and accepted scores as separate evaluation axes. This task supplies no such new labels.

Required controls include all the retained examples above, original nearest-name/logo/missing-current regressions, same-crop/two-world counterexamples, source/crop/frame mismatch rejection, existing cadence/miss/corner behavior, Test 1 ordinary boards, and source edits such as22946's9:12→9:14 without inventing an observed intermediate point. Compare new/missing/wrong observed reads, layout-supported coverage and abstention, raw-token provenance, downstream changes, call count and resource usage. New layout accuracy and digit-level correctness remain null until independently annotated.
