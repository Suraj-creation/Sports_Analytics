## Component changes and limitations

`events/contact.py`: retained the existing contact fusion, thresholds, attribution ambiguity policy, local-maximum suppression and observed/interpolated distinction. Only the finite observed-coordinate gate changes. The geometric racket detector can still alias anatomy/equipment/background; proximity and ellipses remain cues, not impact truth. No trained contact model was added.

`events/contact_evidence.py`: introduced one shared endpoint assessment returning existing typed `ReliabilityAssessment` levels/reasons. A positive externally reviewed impact can qualify; an automatic endpoint needs valid fresh observed context, qualified association and both probable trajectory and impact. Invalid/rejected evidence is rejected and missing evidence is insufficient. Unknown hitter identity alone does not invalidate an otherwise supported temporal endpoint. A weak candidate is still an upper bound for outgoing motion fitting. No mandatory shared schema field is introduced.

`participant_contact.py`: retains all source snapshots and existing episode/court restrictions. Temporal conversion admits only valid boxes and exact-frame pose/racket evidence. Unstamped legacy observations remain missing for temporal pose/equipment use, rather than being silently assumed fresh. This may lower coverage on old caches or independent providers that omit source stamps. Those producers must emit truthful stamps; stamps must not be synthesized merely to restore coverage.

`events/rally_fsm.py`: new exchanges now own independent terminal stationary history. Contact-driven starts, motion-driven starts and a finalized old exchange followed by a new start share that rule. Reopening the same retained segment retains its distinct existing behavior. No gap, minimum duration, lookahead, merge or score threshold was increased to fit reference spans. Rally FPs/FNs caused by absent raw shuttle evidence remain unresolved.

`events/stroke.py`: `jump_features(..., fps=30.0)` is backward-compatible for direct callers at30fps; the integration owner supplies actual session FPS. Arrays must align, and complete observed anatomy is required in both windows. The optional jump-smash assessment remains a 2D heuristic: camera motion, perspective, body-height change and detector jitter can resemble a jump. No physical jump probability or stroke accuracy is established. The baseline `RuleStrokeClassifier` remains heuristic and the integration gate may produce additional explicit unknown classes. Current class taxonomy limitations and perspective-dependent image speed remain.

Rally evidence, short-exchange evidence, outcome and phase files were inspected. Existing selected providers preserve reconstruction as continuation support rather than observed starts/contacts; short-exchange evidence requires source episode separation; existing engine terminal checks withhold unsupported outcome claims. No new source change is claimed in those files. Historical legacy outcome documentation is not an accuracy claim for the current pipeline. No winner or point is synthesized to compensate for uncertainty.
