# Tracking, identity and pose engineering changes — 2026-11-13

This work used static source inspection and retained reports only. No model was loaded or invoked, no videos/frames were decoded, no saved replay/evaluation script was executed, and no tests or benchmarks were run. AST parsing and diff whitespace review establish source syntax only. Accuracy, output counts and runtime effects of these changes remain unverified.

## Changed contracts and files

- `sports/badminton/src/bai_badminton/participation.py`: participant lifecycle separates fresh detector observations from carried estimates. Existing participant IDs and event family/provenance remain compatible; existing participants can still appear in the current frame with estimate-specific confidence/side. A carry does not reset confirmed absence or update stored appearance/position. Entry counts independent detector observations rather than adjacent canonical frame calls. Absence still requires valid overall and detector coverage; unknown/duplicate IDs still cannot establish departure.
- `sports/badminton/src/bai_badminton/identity.py`: freshness gates on provisional initial/spatial/HSV association; copy fresh boxes into retained state so downstream mutation cannot rewrite prior evidence. Unknown negative track IDs remain unbound. This is conservative maintenance of a gated extension, not a newly enabled naming product.
- `sports/badminton/src/bai_badminton/perception/players.py`: RTMPose input/output validation and explicit per-person missing rows. RGB conversion and upstream affine/normalization are preserved. Positive finite SimCC support is kept as emitted, without interpreting it as a calibrated probability. `identity_policy.pose_output` records the behavior revision.

`detector_matched=None` retains the existing legacy caller-coverage behavior for historical/synthetic inputs. Current production has explicit true/false per-person detection provenance. This compatibility path is not a new claim of independent observation. Shared component-version/cache declarations and PosePort's optional row annotation are integrated by the orchestration owner.

## Remaining limits and future empirical work

Installed rtmlib constructs an initial ORT session before the adapter installs configured providers. Its constructor has no session-injection interface; removing the transient duplicate session requires an upstream/custom adapter change. No private-constructor bypass or global monkeypatch was introduced. The configured pose batch setting likewise does not change the upstream per-crop invocation loop; throughput improvements remain unmeasured.

Tracking physical accuracy still lacks independently reviewed persistent four-person identities, boxes and visibility labels. Faster motion, similar uniforms, spectator handovers, cuts, partial court views and long occlusion are not solved by the lifecycle repair. The prior all182 court-origin coverage cases remain evidence to preserve; no speculative covariance gate replaces current continuity. Named identities still require explicit review. No learned identity or pose accuracy improvement is claimed.

Future authorized validation must cover birth confirmation at varying detector cadences, detector-run misses versus scheduled carries, four distinct doubles episodes, unknown/duplicate IDs, false-positive actor handovers, prolonged missing coverage and reset epochs, pose row/order/partial-joint failures, downstream contact/hitter coverage and cache invalidation. These checks were deliberately not executed under this task's prohibition. Entry timestamps may move later because they now require the configured number of independent detector observations; this is an intentional evidence-policy correction whose downstream effects require future measurement.
