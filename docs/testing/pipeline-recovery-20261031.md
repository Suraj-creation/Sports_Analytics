## Boundary contracts

| Boundary | Contract / missing-value semantics |
|---|---|
| Decode -> perception | `uint8` BGR `(H,W,3)`, contiguous zero-based proxy frames; timestamps are derived from canonical FPS. Negative, missing or oversized segment frames fail explicitly. |
| Detector / pose adapters | RF-DETR and RTMPose receive RGB once. Output person boxes are finite, positive-area image-pixel `xyxy`; confidences are retained. YOLOX preserves its BGR preprocessing, raw export scores and pixel rescaling. Malformed output shapes fail at the adapter. |
| Perception -> engine | `ChunkPerception` covers `[start,end]` inclusively and in order. `shuttle_xy=None` is missing; `persons` may be empty. Detector/pose scheduling and individual detector-match provenance are separate fields. |
| Camera -> geometry | Reference court -> image is `H`; reference-image -> current-image is `G`; current court -> image is `G @ H`. Player feet map to court metres. An airborne shuttle is not projected to the ground as a measured landing. |
| Track / identity | Raw tracker ID, canonical visual track, participant observation episode, named P1/P2 hypothesis and team are distinct. Unknown/ambiguous names remain null. Spatial rebind is labelled as an estimate. |
| Shuttle -> semantics | Observed samples differ from spline-filled samples. Internal interpolation has reduced confidence and cannot establish contact motion or a terminal landing. No filled coordinate is persisted as an observed detector hit. |
| Contacts -> shots | `contact_status=estimated`, `racket_contact_observed=false`, heuristic support and per-cue evidence. Lifecycle `confirmed` means ledger finalization, not visually confirmed physical contact. First contact is not automatically a serve. |
| Score -> state | One accepted completed rally produces one point. A cut, EOF, lost airborne shuttle, unsupported terminal or unmapped score is insufficient. Opening server can remain unknown. Corrections refold the authoritative state. |
| Store -> clients | `analysis_revision` increases on reset; `analysis_generation` supports existing clients. New log generations replace old buffers/caches. Durable event paging recovers bus gaps. Empty analysed windows erase old observations. |
| Public motion | Court metres; +x is right viewed from the near end, +y toward the far end. Heading 0°=+x, 90°=+y. Stationary samples have zero velocity and null heading. Latest travel includes frame bounds and `pts_us`, so it is never implicitly a current pose. |

## Validation method and investigated failures

Validation used existing Python 3.12.10 and already available tooling. Compatible cached distributions for `av`, `ulid`, `structlog`, Redis, supervision, trackers, Hypothesis, sortedcontainers and pydeprecate were added only to each validation process's import paths. Nothing was installed or synchronized. `docs/testing/validate_local.py` makes this source-checkout setup explicit, registers the real badminton plugin when installed entry-point metadata is absent, and carries those same paths into CLI child processes. Its optional paths file contains only existing package directories and is machine-specific; the recorded copy is in ignored `.kilo/recovery-20261031/cached-paths.json`.

Tests use temporary databases/data directories and small generated media. No saved user match was reanalysed. Real integration checks exercise ByteTrack, FFmpeg/PyAV, SQLite/Parquet, the real API/engine, WebSocket replay, HTTP media ranges and installed Microsoft Edge. Perception adapter tests use controlled tensors and sessions; they establish interface behavior, not model quality. No pretrained inference or actual CUDA execution was performed.

Representative failing-before / passing-after evidence is retained in ignored `.kilo/recovery-20261031/` logs: historical recovery tests initially had 31 failures; additional adapter contracts had 10 failures, OCR integrity 7, travel-direction tests 15, runtime-device contracts 8, and score-reading integrity 8. Two full-suite failures came from source-checkout execution rather than production substitutions: the real plugin was not discoverable without installed entry-point metadata, and three research CLI tests lacked inherited source/dependency paths. The original browser specs predated the current product titles and branding. Their selectors now follow current accessible controls. An additional collision was caused by uploading identical fixture bytes twice: the API correctly reopened the saved session and its original metadata. Missing Playwright Chromium was handled through the existing `PW_CHANNEL=msedge` option, using installed Edge; no browser was downloaded. The disposable E2E server and its temporary session stores were stopped after validation.

An independent read-only review found the historical score-row mapping and contact-eligibility ordering defects. Both received targeted failing regressions, repairs, and passing follow-up review. The follow-up examined the 63-test passing evidence; it did not claim neural accuracy or repeat the entire suite.

## CUDA readiness: inspected versus executed

`engine/runtime/device.py` retains the configured ONNX provider order and device options, including the existing Pascal-compatible environment assumptions. `ort_runtime` now records the session's actual providers, actual backend, and fallback status. Player/pose/OCR/TrackNet loaders publish their actual runtime through capability metadata rather than merely echoing the requested backend.

The TrackNet Torch loader honors requested FP32 versus FP16 when selecting CUDA, moves inputs to the loaded parameter device/dtype, and reports CPU fallback explicitly. Controlled Torch/ORT tests verify selection, precision, input placement, provider reporting, disabled-stage behavior and fallback metadata. These tests do not allocate CUDA tensors or measure a kernel. A host CPU provider list cannot establish TensorRT support, Pascal compatibility, GPU memory sufficiency or real inference speed. Those require the unchanged server environment and the sequence below.

## Remaining critical/high-severity limitations

1. **Real perception accuracy and CUDA are externally unverified.** No real player, pose, shuttle, neural identity or pretrained stroke model was executed for this task. Missing `rtmlib`/RapidOCR prevented their real adapter tests. Real weights/data/hardware are the missing evidence; installing or downloading them locally was expressly prohibited.
2. **Physical racket–shuttle contact is not observed.** There is no connected trained racket adapter. Motion/proximity/pose can only estimate hits. This is now represented honestly; synthetic tests cannot establish physical contact accuracy.
3. **Live shot labels remain heuristic.** Restored BST is a bounded, explicit singles research path. Promoting it without the checkpoint, suitable temporal observations and held-out results would invent validation. Doubles pretrained classification is unsupported.
4. **Four-person durable identity and partner service rotation are unresolved capabilities.** Four visual tracks and team hypotheses do not establish named identities through crossings/fragmentation, or BWF doubles partner rotation. Current safeguards withhold unsupported individual claims.
5. **Automatic visual scoring remains an estimate with missing coverage.** Observed stationary terminals are stronger evidence than disappeared airborne positions, but detector false positives, foot/court error and ambiguous net/outside decisions can still be wrong. Unsupported points remain unresolved. Broadcast OCR and explicit human correction remain separate evidence paths.
