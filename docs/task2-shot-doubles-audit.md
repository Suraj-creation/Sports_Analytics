# Task 2: shot and individual-player analytics audit

Status: investigation and incremental evidence-integrity changes in progress. This is not an accuracy validation or a completed four-player implementation. No before/after shot-accuracy claim can be made without reviewed per-shot ground truth and a repeatable evaluation by recording.

## Current processing path and limitations

- `sports/badminton/src/bai_badminton/identity.py` selects at most one player on each side and assigns P1/P2. `sports/badminton/src/bai_badminton/engine.py` carries P1/P2 buffers and uses the nearest player at contact. This cannot maintain four individual identities through doubles rotation, crossing, occlusion, track changes or substitutions. Court side is not a persistent individual identity. Ambiguous attribution needs an explicit unresolved state.
- `sports/badminton/src/bai_badminton/events/contact.py` derives candidate contact from observed, non-interpolated shuttle movement and temporal velocity/impulse, augmented by proximity to a wrist or upper body and swing evidence. It has no localized racket evidence and proximity alone does not establish the hitter, especially when partners are close. Missing or occluded shuttle samples can prevent contact detection.
- The default classifier in `sports/badminton/src/bai_badminton/events/stroke.py` is deterministic: it uses court depth, normalized post-contact image speed, flight duration and approximate above-head evidence. It produces softmax scores with a capped top score, not demonstrated calibrated probabilities. The event engine constructs a stroke after subsequent temporal evidence becomes available (`engine.py`). It does not prove racket–shuttle contact or reliably distinguish similar strokes from appearance and motion alone. The source docstring references `bai_badminton.perception.bst`, but that module is not present; the reference does not demonstrate an installed classifier.
- `sports/badminton/src/bai_badminton/ontology.yaml` defines short and long serve, smash, drop, clear, lift, drive, push, net kill (`rush`), net shot, cross-court net shot, block and unknown. `cross_net` mixes direction into the shot-class list. Variations, placement and rally outcome need distinct evidence-backed fields; no class or outcome should be inferred solely from another.
- `sports/badminton/src/bai_badminton/analytics/match.py` aggregates current stroke records into two player slots; these slots are not verified doubles teams and cannot recover four individual players. Spatial analytics depend on valid calibration; receiver-position proxies must not be represented as observed landing points. Review `apps/api/src/bai_api/routes/sessions.py` and `apps/web/src/features/analytics/SessionAnalytics.tsx` along with the event ledger when extending the contract and interface.

## Incremental integrity changes under validation

The current changes are safeguards, not a measured shot-classification improvement: the rules classifier abstains as `unknown` when essential flight evidence, or for non-serves valid court position and speed, is missing; unknown classification has no asserted classification confidence and records a reason. Shuttle kinematics ignore interpolated points. Contact and stroke records retain the temporary detection track ID when available, as provenance rather than a stable participant identity. Session PATCH preserves the existing player list and metadata. Match analytics now exposes attributed, unattributed and total shot accounting for official, owned, current canonical strokes. Focused tests cover these changes, including duplicate and correction behavior, in `sports/badminton/tests/test_engine.py`, `test_temporal.py`, `test_analytics_integrity.py` and `apps/api/tests/test_api.py`. An earlier focused run passed 72 tests before the track-provenance change; comprehensive tests remain in progress. These safeguards do not implement four-player tracking or resolve uncertain contacts.

## Baseline and evaluation

`research/evaluation/sample-rally-draft.json` is an unverified rally draft, not reviewed shot-level ground truth. A shot benchmark evaluator (`research/shot_benchmark.py`) and annotation protocol (`research/shot-annotation-protocol.md`) are available; they require reviewed labels before they can measure accuracy. No reviewed per-shot labels were identified in this audit. Create a representative singles/doubles set with reviewer-verified contacts, stroke families and hitter identities, ambiguous/occluded cases, recording-level splits and a written annotation protocol. Freeze the baseline and use the same recordings and scoring protocol after changes. Report per-class precision/recall, macro-F1 and confusion matrix; unknown/low-confidence share; contact detection and timing; hitter attribution and coverage; player/team reconciliation; latency and peak GPU memory. Separate uncertain or unobservable cases, and disclose sample sizes. Geometric court-exclusion metrics are not labelled shuttle or event accuracy. Back up existing session results before reanalysis, and do not overwrite historical outputs silently.

## Cached replay comparison

A CPU semantic replay of five cached recordings compared baseline revision `d932684` with the current implementation. The current replay produced 766 stroke events in total. The baseline produced zero unknown classifications; the current version produced 108, distributed by recording as 1/2, 13/268, 24/235, 70/261 and 0/0 (unknown/total). Rally, point and stroke event counts were unchanged. This checks the semantic impact of abstention; it does not establish whether any classification is correct or demonstrate an accuracy improvement. It did not run new GPU inference or mutate historical sessions. Temporary replay stores are under `/tmp/bai-task2-replay.wnGSUx`; saved reports and reproduction instructions are in `docs/testing/task2/`. In addition to the 108 labels changed to unknown, 19 changed between non-unknown classes after excluding interpolated shuttle points. Of matched events, track IDs were present in 0/766 strokes and 0/767 contacts before, and 766/766 strokes and 767/767 contacts after; this is track provenance, not verified participant identity. The full repository suite passed 290 tests with two warnings; the standalone benchmark tests were also rerun after its fractional-frame-rate fix (13 passed).

## Candidate model decision

- [Laya](https://huggingface.co/convaiinnovations/laya): Apache-2.0; the root checkpoint is a 421M text/structured-state typed-decision model. It returns choice probabilities, not generated explanations, and cannot directly read the video. Its card reports poor zero-shot performance on a typed-decision benchmark and overconfidence before recalibration. Test only if structured visual features and held-out labels show added value over deterministic or compact supervised alternatives.
- [Cloudflare CLEF](https://huggingface.co/Cloudflare/clef): Apache-2.0, 27B multimodal model supporting text, JSON, images and video with typed option logits, not free-form explanations. Its card describes testing on H200 with PyTorch 2.11 and Transformers 5.10.2. [CLEF-Flash](https://huggingface.co/Cloudflare/clef-flash) is a 9B multimodal Apache-2.0 alternative. Neither card establishes badminton shot accuracy or performance on this server; a bounded uncertain-case comparison is a research candidate, not a production selection.
- Jev is excluded from this task at the user's request.

The server reported two GTX 1080 Ti GPUs, each with 11,264 MiB; one had 2,456 MiB in use at inspection. These Pascal devices lack native BF16 acceleration, and model-card H200 figures cannot be treated as local latency or memory measurements. No candidate inference or local model benchmark was run in this audit. Preserve the configured CUDA/FFmpeg environment and other workloads; do not replace dependencies or introduce large-model inference on every shot without demonstrated benefit and a bounded failure path.
