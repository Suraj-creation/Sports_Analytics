## Concrete migration and behavior

The existing `BAI_LLM_BUDGET_TOKENS_PER_SESSION` keeps its400000 default and gains a nonnegative constraint. New `BAI_LLM_BUDGET_MODE` defaults to `reported`. New `BAI_LLM_MAX_OUTPUT_TOKENS_PER_CALL` defaults toNone; leave it unset to preserve adapter defaults: Anthropic16000 and OpenAI-compatible4096. Explicit positive overrides are supported. No model, profile or weights change.

Reported mode preserves configured native providers. It reserves a requested output envelope before **each** generation/repair call and permits one unknown-input in-flight call per session. It settles complete provider-reported total tokens immediately, including all disjoint Anthropic input/cache/output categories or OpenAI's prompt-plus-completion total. OpenAI cached/write details are subsets and are not added a second time. The counter can cross its limit on one response because input tokens were not known before dispatch. It then refuses later calls. This is prospective reported-usage admission, **not a pre-dispatch total-token or currency billing hard cap**. [OpenAI usage reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events), [Anthropic cache usage semantics](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

Unknown/missing/inconsistent usage or an exception after dispatch is never treated as zero. Reported mode keeps the durable pending output reservation, records known components, marks uncertainty and refuses future model calls. It does not automatically retry, refund, expire a lease or delete uncertainty. Deterministic summaries remain available. Current native SDK constructors explicitly use zero automatic transport retries and a30-second I/O timeout. That is not a process-wide wall-clock deadline or proof about provider-internal routing.

Strict mode is an explicit opt-in. It requires a typed provider capability attesting a conservative upper bound for the exact full request, no automatic retries and an enforced output cap. It reserves the input bound plus requested output before dispatch. Current native adapters do not attest this contract; `/ask/provider` reports strict unavailability and calls fall back deterministically. No character estimate or different counting endpoint is silently substituted. Independent providers remain injectable and can expose the explicit capability; a declared contract still requires backend validation.

The dedicated `data/llm_budget/<session_id>.sqlite` reuses the existing EventStore schema/public transaction/meta APIs; existing analysis databases need no schema migration. Its short `BEGIN IMMEDIATE` transactions serialize independent connections/processes. No DB or repository lock spans counting or generation. The ledger outlives analysis reset/restore, and its scope explicitly says `from_ledger_creation;prior_usage_unknown`. It cannot reconstruct earlier unmetered usage. Backups/retention must include this new directory; deleting/resetting the analysis must never replenish it. Uncertain accounting needs explicit review/reconciliation; no unsafe reset/refund endpoint is supplied.

Every successful turn settles before the loop proceeds. Earlier successful usage remains counted when a later turn fails or a stale answer is withheld by the existing event-sequence fence. The API keeps its answer/citation behavior and adds policy/strict-capability disclosure to provider information. Configured provider availability and per-call admission remain distinct.

## Executed validation and scope

The unchanged production provider constructors fail four single-attempt/timeout controls; the copied candidate passes them. Original logs are retained. The frozen v1 broader shadow suite passes93tests, with one existing media encode test intentionally deselected and three existing Starlette deprecation warnings. The v2 focused run passes53controls in4.04seconds, including ten new regressions that fail on v1. Ruff passes. The broader merged-root suite is deliberately left to the orchestrator after review/application. No model, remote inference, token count endpoint, credential request, external service or encode is invoked. SDK/client transports are scripted.

Controls include actual EventStore threads and independent processes, reopen/crash reservations, malformed state, unknown/invalid usage, total overrun, per-session isolation, analysis reset, seven calls including repair, later failure, explicit retry, no network-wait DB lock, stale publication charging, native adapter accounting/refusal, default reported availability/output preservation and strict unsupported fallback. Copied-engine/API imports are asserted. The shadow suite cannot substitute for merged-root testing or remote vendor behavior.

Root review reproduced two v1 edge cases. V2 adds a distinct `TokenRequestTooLargeError` with code `request_too_large`, which reported mode cannot downgrade to unknown identity. It rejects both complete serialized requests over1MB and a known-literal-byte lower bound over1MB even when unrelated opaque history lacks exact identity. This resource bound is not a token-count approximation. Eight mode/shape regressions prove zero provider dispatch, zero charge and no reservation for large system text, combined history, escaped JSON and opaque history.

V2 also rejects a known OpenAI cache-read or cache-write subset larger than the prompt as incomplete/unknown usage. The reported numeric subset remains visible, never replaced with zero; total settlement is withheld and subsequent calls block. Two regression cases exercise both normalizer state and durable unknown handling. The complete v2 review delta changes only `budget.py`, `accounting.py` and these regression tests relative to v1.
